# LTB Case Finder

A case discovery tool that helps Ontario residential tenants find past Landlord and Tenant Board (LTB) orders related to their rental issue — without needing to know LTB legal terminology or application codes.

## The Problem

Ontario tenants dealing with a rental issue (unpaid maintenance, an eviction notice, a rent dispute, etc.) often don't know that a public catalogue of past LTB decisions exists, and even if they find it, the catalogue is organized by legal application codes (`T2`, `L1`, `A4`...) that aren't meaningful to someone without legal training. LTB Case Finder closes that gap: a tenant describes their issue in plain language, and the tool surfaces relevant past orders for them to read.

**This is a research tool, not legal advice.** It does not determine outcomes, does not interpret orders, and does not guarantee that a similar past decision will apply to any individual's situation. See [Scope & Legal Boundaries](#scope--legal-boundaries).

## How It Works

1. The tenant selects one or more issue categories from a predefined list.
2. The app finds LTB orders whose application codes match the selected categories.
3. Cases matching **all** selected categories are prioritized; if fewer than 20 exist, cases matching **at least one** category fill the remaining slots.
4. Results are ordered by most recent order date, capped at **20 cases**.
5. The tenant can open the original order document for any result.

## Issue Categories

The interface presents these user-facing categories, listed alphabetically (backed by official LTB application codes internally — see [`config/issue_taxonomy.json`](config/issue_taxonomy.json) and [`config/README.md`](config/README.md) for the full code mapping and sources):

## Results

Each result displays:

| File Number | Order Date | Issues | Forms | City | Resident Type | Document Type | View Order |
| ----------- | ---------- | ------ | ----- | ---- | -------------- | -------------- | ---------- |

* **Issues** shows human-readable category names (e.g. `Maintenance · Tenant Rights`) rather than raw application codes.
* **Forms** shows the raw LTB application codes for the order (e.g. `T2 · T6`) — useful once a tenant knows the terminology.
* **Resident Type** is `Rental Unit` or `Complex`, derived from which address field the catalogue populated for that order.
* **View Order** links directly to the original order document (no parsing or analysis of its contents — see [Data Source](#data-source)).

The application codes and address data remain available internally for filtering, ranking, and city derivation; only the columns above are shown to the user.

## Data Source

[Ontario Open Data — LTB Order Catalogue](https://data.ontario.ca/). The app uses this catalogue's metadata (file number, order date, application codes, city, document type, document URL) to find and link to orders. It does not download, parse, or analyze the contents of the order PDFs themselves — `View Order` links straight to the source document.

## Getting Started

**Prerequisites:** Python 3.11+. Commands below use Windows paths (`.venv\Scripts\...`); on macOS/Linux use `.venv/bin/...` instead.

1. **Install dependencies**
   ```
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```
2. **Get a raw catalogue snapshot** (Task 2) — the CSV isn't committed to git, so download it into `data/raw/`:
   ```
   curl -L -o data/raw/ltb_2026.csv "https://data.ontario.ca/datastore/dump/86e75d11-1c2c-4cd9-9b0d-9fccec302b30?bom=True"
   ```
   See [`data/raw/README.md`](data/raw/README.md) for details on this source.
3. **Build the local database** (Tasks 4–6) — reads the raw CSV, cleans and normalizes it per the schema in [`data/schema.sql`](data/schema.sql), and writes `data/ltb.db`. Safe to re-run any time the raw snapshot changes:
   ```
   .venv\Scripts\python.exe scripts\ingest_catalogue.py
   ```
4. **Start the backend API**
   ```
   .venv\Scripts\python.exe -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
   ```
   Confirm it's up: `curl http://127.0.0.1:8000/health` should return `{"status":"ok"}`.
5. **Serve the frontend** — from a second terminal, serve `frontend/` over HTTP (the backend's CORS is configured for cross-origin requests, and a real HTTP origin avoids `file://` fetch quirks in some browsers):
   ```
   cd frontend
   python -m http.server 5500
   ```
   Then open `http://127.0.0.1:5500/index.html` in a browser.
6. **Try it** — select one or more issues (e.g. `Maintenance`) and click **Search**. You should see a results table; selecting a category with no matches shows a "No matching orders found" message instead.

Run the test suite with:
```
.venv\Scripts\python.exe -m pytest -v
```

## Scope & Legal Boundaries

MVP 0 is intentionally limited. It does **not**:

* Analyze order documents (no PDF parsing, no OCR)
* Use TF-IDF, cosine similarity, or any LLM
* Provide legal advice, predict case outcomes, or recommend legal action
* Interpret an order or claim a past decision will apply to a user's situation
* Require user accounts or authentication
* Return more than 20 results per search

The application exists to help tenants **find relevant LTB orders for further research** — not to determine the outcome of their own case. This disclaimer is also shown as a persistent banner in the app itself, not just here.
